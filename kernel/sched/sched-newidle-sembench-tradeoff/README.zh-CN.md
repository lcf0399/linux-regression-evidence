# sembench 高并发与 new-idle 均衡取舍

状态：11月5日完成最终离线验收，主要策略归因与v4匹配验证已收尾；用户已确认发送上游补充报告，
已移出candidate并归入调度子系统。实际发送头、公开归档及后续回复尚未独立核验，见
[上游状态](upstream-status/README.zh-CN.md)。
发现来源是 **MMTests／sembench 原生benchmark**，不是模型生成的研究场景。

原生815-worker futex负载中，固定worker轮转绑定全机逻辑CPU，可迁移的主线程集中扫描和唤醒。
抑制new-idle均衡尝试会改变主唤醒者的迁移与竞争状态，降低这组高并发吞吐。

| 已完成对照 | 结果 |
| --- | --- |
| 7.3同镜像NI_RANDOM开→关→开，8／815-worker | 高并发关闭后均值+23.48%，回切−0.31%；小规模+0.34%。关闭组CV7.18%，全部九次均高于基线 |
| 匹配6.15.11与上游撤回d206fbad | 350／815-worker分别+14.03%／+17.18%，小规模约+1%；首段成本来源155213a2aed4明确 |
| 独立主线程及迁移栈诊断 | 看到其他CPU通过new-idle实际拉取主唤醒者；撤回后主线程CPU／完成量和切换／完成量减少 |
| 7.3匹配基线→Bresenham v4→基线，54份正式样本 | 815-worker仅+1.98%，未恢复主要慢差；8-worker均值+7.68%，补丁组CV3.32% |

7.3采用后继概率策略，不是155213的旧代码一直保留；这些结果不能相减成全部历史差值的分解。
重点报告最新端的可重复策略取舍，历史撤回作为背景。关闭NI_RANDOM仅为归因控制，不建议默认关闭。
本轮归因验收覆盖“首段引入修改→匹配恢复”“最新策略开关→吞吐恢复”“主唤醒者迁移／切换路径”三层证据。
结论是跳过均衡削减了此负载中有用的迁移机会，而不是futex本身统一变慢；不再为已回答的问题重跑完整矩阵。
各代策略的收益不相加，也不将尚未逐项分解的全部历史26%差距伪装成某一枚提交的独占成本。

报告准备完成不等于上游已经确认或修复。

## 已完成的有界补丁验证

对[Qing Wang的v4](https://lkml.iu.edu/hypermail/linux/kernel/2610.3/14236.html)测试匹配的7.3基线→v4→基线，
只取8／815-worker原生条件，每端每条件九次。NI_RANDOM／NI_RATE均保留开启。
v4改变选择均衡时机的方式，同时有边界／尝试频率差异，不能当作只改变随机性而其他完全不变。
2026-11-02 07:58:39 UTC完成54份正式样本、独立原始复算及generic恢复。
815-worker的基线A／v4／基线B为1,112,251／1,136,952／1,117,457次／秒，均值提高1.982%，
最大CV1.244%，回切差0.468%；只改善约2.21万次／秒，没有恢复主要高并发慢差。
8-worker为2,668,465／2,876,585／2,674,225次／秒，均值提高7.683%，但v4组CV3.325%，不固定精确收益。
完整运行时间均约29.65秒。没有新增实际均衡频率诊断，不把这些结果解释成已经证明“仅随机性”是原因。
进度及冻结合同见实验记录（本地记录）。
首轮仅因产物收集清单错误停在安装前；修正后的r2保持原补丁及测试范围，不改既有归因结果。
