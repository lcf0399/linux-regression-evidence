# AppArmor 提前返回原型：2026-09-21～22

固定 v7.3-rc4 基线下，原型使不受限 socketpair 发送段快 **12.84%**；另一组双进程
测试中，双方受限但允许通信时慢 **1.25%**。已完成的权限测试未发现与原版不同的结果。
这是供审阅的原型，不是全面安全证明，也不代表实际应用整体收益。

## 同基线原型对照

两组实验都按原版 A → 补丁 B → 原版 A2 独立启动。基线为
`93f51579e7df248780214094418f205253383cc5`（v7.3-rc4）；GCC 15.2.0、源码基线及
配置匹配，仅 `CONFIG_LOCALVERSION` 不同。[补丁](early-unconfined.patch)与实际测试
文件逐字节一致。它在 `aa_unix_peer_perm()` 判断整个标签是否 unconfined，保留双向
权限检查，不增加每对象字段。

单位为 ns/message，越小越好；变化相对两次原版的中点。两种 workload 分开解释。

| 场景 | 原版 A | 补丁 | 原版 A2 | 变化 |
| --- | ---: | ---: | ---: | ---: |
| socketpair，双方不受限 | 416.073 | 359.448 | 408.719 | −12.84% |
| 双进程，双方不受限 | 455.537 | 412.052 | 455.592 | −9.55% |
| 双进程，仅发送方受限 | 569.749 | 561.786 | 570.054 | −1.42% |
| 双进程，仅接收方受限 | 576.514 | 562.807 | 579.974 | −2.67% |
| 双进程，双方受限 | 740.810 | 750.620 | 741.959 | +1.25% |

socketpair 每条节省 52.95 ns，最大组内 CV 0.114%，原版启动间漂移 1.78%。双进程
四个条件最大组内 CV 1.80%、最大漂移 0.60%。双方受限时每条多 9.24 ns，最大组内
CV 0.515%、漂移 0.155%；去掉每份调用的首个正式样本后仍慢 1.255%。主结果使用全部
正式样本，不因代价低于 5% 就记为没有影响。

## 测试设置

- i7-12700KF、32 GiB 内存、20 个逻辑 CPU 在线；实际 full preemption，governor/EPP
  为 performance，关闭 Turbo。发送 CPU 2；双进程接收 CPU 4，位于另一物理 P-core。
- socketpair 沿用[原 standalone 源码](../../reproducer/af_unix_sendmmsg_standalone.c)，
  `socketpair(AF_UNIX, SOCK_DGRAM)`，不受限。
- 双进程使用连接的抽象地址 AF_UNIX 数据报 socket；先进入单标签，再降为 UID/GID 1000、
  清空附加组并设置 `no_new_privs`，之后创建 socket。计时中的受限策略允许通信。
- 每条件每启动三份，每份预热 3 轮、正式 15 轮；每轮 65,536 条，每批 32 条，每条 128 字节。
- 只计 `sendmmsg()`。准备、排空、内容校验和管道协调都在计时外；命中探针与计时分开。

## 正确性与命中

两组原型对照的六次启动各通过 29 项静态控制，包括受限/不受限组合、堆叠标签、数据报/流式
socket、新旧 ABI。细粒度 UNIX 策略使用 ABI 5.0（`network_v9`），旧 ABI 控制使用
`kernel-5.4-vanilla`。

双进程补测每启动增加 84 次存活 socket 固定阶段检查，三点决策相同，没有跳过阶段，关闭时
没有积压消息。另有每启动两组、每组两秒的并发检查，每组 16 次替换均发生在发送循环内。
发送方策略变化时观察到允许和拒绝；固定发送方拒绝、同时改变接收方策略时，成功发送为零。

仅替换接收方为拒绝策略后，已有 socket 在原版和补丁版都仍可接收。这条路径使用接收
socket 保存的标签，因此这里验证的是**原版行为一致，不是即时撤权**。存活堆叠标签更新、
不同命名空间、全部 socket 类型及所有并发交错没有覆盖。

socketpair 探针三点外层计数均为 1,056 / 2,112，内部 `unix_peer_perm()` 为
2,112 → 0 → 2,112。双进程每窗口发送 1,024 条，外层计数均为 1,024 / 2,048；内部在
原版均为 2,048，补丁按表中四种双进程条件分别为 0 / 1,024 / 1,024 / 2,048。
这些窗口均未混入正式计时。

## 独立的原回归复测

另一次四点启动为旧快端 A → 原慢端 → v7.3-rc4 → 旧快端 B；使用相同 standalone
程序、采样设置及 full preemption，不能与上述原型百分比相减。

| 点 | ns/message |
| --- | ---: |
| 旧快端 A（`0bfa1c2da7a8`） | 342.422 |
| 原慢端（`30cb02a874b4`） | 390.530 |
| v7.3-rc4（`93f51579e7df`） | 413.677 |
| 旧快端 B | 345.043 |

`6456ccbd2ff7` 的受控源码增量仍慢 13.61%；整版比较慢 20.35%，后者包含其他源码和
配置变化，不能全部归因于该提交。最大合并 CV 0.264%，快端 B/A 漂移 +0.765%。旧报告的
preempt=none 数据保持原样，不与本轮混算。

## 文件与复核

- [summary.tsv](summary.tsv)：七项比较，包含漂移、CV、去首样本检查。
- [samples.tsv](samples.tsv)：三组实验全部 855 条正式观测，另保留双进程的 108 条预热。
  socketpair 程序执行预热，但只输出正式观测。
- [run-identity.json](run-identity.json)：源码、构建、十次独立启动、环境和二进制身份。
- [validation.json](validation.json)：精简语义记录、命中计数、并发结果及预检失败说明。
- [reproducer/](reproducer/README.md)：未经修改的双进程源码与权限检查程序。大型原始日志、
  构建及失败目录保留在实验归档，不重复搬入。

运行 `python3 verify.py` 可从 elapsed_ns 独立重算结果，核对样本清单、启动身份和
源码/补丁校验值；它不重新执行内核权限测试。准备本目录前，已另行重跑原始输出审计。

CV 为样本标准差/均值。原型漂移按 `abs(A2-A)/中点`，原回归复测保留既有 `(B/A-1)`
定义。预热不计入均值，每份正式 15 轮全部保留。实验结束后已恢复 generic、原电源和启动设置。
