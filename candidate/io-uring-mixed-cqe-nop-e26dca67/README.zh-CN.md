## 可报告的结论

`e26dca67fde194340582cfbb0c0bf661825e9e46`
（`io_uring: add support for IORING_SETUP_CQE_MIXED`）在未启用混合／宽CQE的
原生20线程NOP条件下，导致吞吐下降 **5.564%**，每秒少约2957万次接受提交。

| 精确父／子／父 | 百万NOP提交/秒 | 组内CV |
| --- | ---: | ---: |
| 父版`89a885972140`，首次启动 | 531.605 | 0.145% |
| 子版`e26dca67fde1` | 501.944 | 0.045% |
| 同一父版，独立回切 | 531.432 | 0.066% |

每端独立启动、100秒预热、9次100秒调用；回切漂移−0.0324%。本轮重新从27份原始输出
及完整调用计时独立复算通过。程序固定时长，收益／损失体现为完成的操作量，不是100秒变短／变长。

提交没有修改NOP实现，父子`nop.o`逐字节相同。改变的是共享完成路径：即使只写16字节CQE，
仍需解析宽度标志、以指针差计算可用槽位并走新增格式／边界检查。
匹配机器码中，缓存仍有空间的普通完成循环由20条变35条静态指令，条件分支4个变6个；
这是成本解释，不把全部5.564%独占归给某条表达式。

## 与其余NOP结果的关系

- 6.12.95→7.3的原生20线程两轮筛查下降20.03%／22.12%；本提交只解释其中一个明确历史来源。
- 紧接的NOP_CQE32扩展`806ecb209aa8`另有稳定1.565%成本，不能与本项百分比简单相加。
- 7.3保留功能的零标志短路径与公共issue内联分别改善了吞吐；它们是优化对照，不是历史提交净效应。
- 容量判断等价改写在7.3原生20线程下改善方向一致，但回切漂移−2.293%未过事前门槛，
  不将均值4.193%写成稳定收益或本提交的全部可恢复份额。
- 旧单线程、Turbo开启的公共CQE对照接近持平；不能外推到本轮20线程、非Turbo条件，
  也没有把两者差异仅归因于线程数。
