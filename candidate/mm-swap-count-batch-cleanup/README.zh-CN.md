# F01：合并共享 swap 计数表的重复清理检查

优化讨论候选，尚未发送上游。它与 F02 的“大页换出页序”是两个独立原型，没有叠加测试。

## 做了什么，有多大价值

多个进程共享换出的页时，内核需要记录还有多少引用。计数较大时使用扩展表。
现有上游方案已让检查在遇到第一个非零项时退出；但一次解除16页映射，仍可能反复检查同一张表。
本原型在同一把 cluster 锁内合并这些检查，在释放槽位和解锁之前处理；其他调用者保持即时检查。
保留15→14、14→13两个必要阈值，不删除扩展表生命周期的保护。

固定 MM 维护树 `2967f3ccdb5fae956f1b085370ec292bab5c7e25`（7.3-rc5）原版已包含作者的提前退出方案。
与仅加本原型的版本做原版A→原型→原版B：高计数组每次解除16页映射为
**3.307→2.337→3.222 µs**。相对两端原版合并均值3.264 µs，平均省 **0.927 µs（28.39%）**。

这是有明确机制和局部收益的技术讨论候选，不是应用加速结论。槽位位置影响收益，原版CV为
14.04%／16.55%，原型4.93%，回切漂移−2.56%；样本范围仍重叠，不能外推固定28.39%。
8持有者控制没有明确变化。此前旧v7.2无锚点完整释放实验也没有证明明确整体收益，不能冒充新树结果。

## 场景与边界

程序准备33个私有4 KiB页，选同一cluster内17个连续换出槽位，丢弃其余页后创建14个子进程。
三个子进程依次解除其中16页的映射；所有持有者保留第1页，因此计时期间扩展表不能释放。
这是为了隔离重复检查的合成条件，不是已确认常见的生产工作负载。

新树两端另有8次状态／入口检查、12次最后高计数释放／混合／双CPU并发边界检查，
观察到最终扩展表在解锁前释放、计数及内容正常；不代表穷尽配置、竞态或分配失败。
性能计时没有探针，只计系统调用返回，不包含准备、fork、协调和最终清理。
