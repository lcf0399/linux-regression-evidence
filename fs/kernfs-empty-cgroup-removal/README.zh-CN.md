# kernfs：空 cgroup 删除成本增加

原报告已于 2026-09-13 发送，2026-09-14 完成独立的 INODE_INITED 补丁验证，见下表。
9 月 16 日的独立 inode 请求标记原型另有[结果与未覆盖项](bare-metal/inode-requested/README.zh-CN.md)。
原型回复及原始补丁附件已于 9 月 17 日发送，见[上游状态](upstream-status/README.zh-CN.md)；仍是待审阅方案。
这是一份性能成本报告，不建议撤销原修复，
也不代表新增成本全部可以消除。

两轮独立裸机实验确认，两个相邻 kernfs 修改使空 cgroup v2 叶子组的删除慢约 46%～48%：

- `507d8ce13f5b91d5b4dca7bd4b4e4249e8021cca`：删除目录期间保护 inode 链接计数；
- `eea5d2bb34ba11dccd9c53f392dc50cf060150a9`：补齐删除通知及 inotify watch 自动清理。

它们有正确性目的。这里分别记录“实际增加多少成本”和“能否保留功能并优化”，不建议撤销修复。
该场景来自 sched_ext 的 cgroup 操作探索，但关闭 sched_ext 后仍有相同增幅，不能归因于 ext.c 独有路径。

第二轮精确对照，关闭 sched_ext；表中为每次启动九份样本均值的中位数：

| 源码状态 | boot A，µs/rmdir | boot B，µs/rmdir |
| --- | ---: | ---: |
| 两个修改之前，`f917dc56060a` | 6.504 | 6.528 |
| 加入链接计数保护，`507d8ce13f5b` | 6.956 | 6.922 |
| 再加入删除通知，`eea5d2bb34ba` | 9.553 | 9.558 |

绝对增加约 3 µs/次，不是应用或完整容器销毁慢 46%。叶子组中没有任务或子组；
25 个控制文件由内核自动创建，因此一次删除涉及 26 个 kernfs 节点。
创建、删除分别计时，状态核对放在计时外。

## 各项结果分开看

| 实验 | 结果 | 边界 |
| --- | --- | --- |
| 两轮六次启动的精确提交对照 | 四种删除条件均通过 CV 3%、漂移 2%、效应 5% 及 drop-first 检查 | 证明成本增加，不证明原来的速度能在保留修复后完全恢复 |
| 本地 root 复用原型，一轮四次启动 | 保留锁、查找和通知，删除快约 4%～5% | 未在全部比较中达到 5%；并发正确性验证未齐，不是已提交修复 |
| v7.2 → 固定 7.3-rc2 → v7.2 | 9.919 / 9.719 / 9.953 µs；改善 2.019% / 2.355% | 独立的一轮版本比较，不能把旧精确 46%～48% 直接套到新版 |
| [INODE_INITED 补丁验证](bare-metal/inode-inited/README.zh-CN.md)，两个每份 128 次的独立四点实验 | 原程序删除快 21.87%～22.86%；分阶段补测的连续删除快 22.17%～22.37% | 这些连续整段结果仍不稳定；间隔版整体改善 1.38%～2.72%。基本语义通过，不是完整并发安全或全部修复结论 |
| [INODE_INITED 预热／间隔诊断](bare-metal/inode-inited/pacing/README.zh-CN.md)，另立每份 32 次的四点矩阵 | 预热 16 次、连续整段快 5.77%～8.76%，最大 CV 1.76%、漂移均低于 2%；六条件删除均省 2.10～2.58 µs | 旧不稳定结果与不预热条件均保留；这是节奏敏感性诊断，不是应用级收益或完整修复 |
| [独立 inode 请求标记](bare-metal/inode-requested/README.zh-CN.md)，9 月 16 日一轮四点矩阵 | 原程序删除耗时降低 22.36%～22.72%，连续整段降低 7.35%～9.01%；有界 FD、通知与首次创建检查通过 | 每节点增加 8 字节；首次文件查询计时不稳定；关键锁交错及其他用户/架构仍未验证，不是已完成修复 |

创建指标及不稳定的次要结果同样保留，不把不同实验的样本合池。
