# INODE_INITED 补丁验证

2026-09-14：T.J. 的改动使原 binary 的空 cgroup 删除快 **21.87%～22.86%**。
独立的分阶段补测再次确认删除改善；连续操作的整段计时仍有噪声，不能把删除收益当成整体收益。
这不是完整并发正确性证明，也不宣布原回归已经完全修复。

## 对照与方法

共同基线为 `2f0c1cf72f4682178506f513bbf015e591b1aa4a`（7.3-rc2）。
A 加入 Shakeel 的文件句柄入口读锁修复，B 再加 T.J. 原版 INODE_INITED 改动。
未测 T.J.-only 内核；作者完整基线仍未知。[补丁](patches/)来自实际编译源码差异，
未改变作者逻辑；原补丁与编译源码 SHA 见 [identity.json](identity.json)及[来源清单](provenance.json)。

i7-12700KF 裸机、CPU0、SCX 关闭、full 抢占、performance governor、Turbo 关闭，
GCC 15.2，配置仅 LOCALVERSION 不同。两项实验分别完成 A1→B1→B2→A2，
每点独立启动，每条件九份样本，每份 16 次预热＋128 次正式操作，结束恢复 generic。
两项实验使用不同 binary，样本不混合；间隔与连续条件属于同一次辅助矩阵。

## 结果

下列微秒值为九份样本均值的中位数，顺序 A1 / B1 / B2 / A2。

| 实验、指标 | 四点结果，µs | 结论 |
| --- | --- | --- |
| 原 binary，rmdir | 9.727 / 7.600 / 7.548 / 9.784 | 快 21.87%～22.86%；最大 CV 2.027%，A/B 漂移 +0.588% / −0.680% |
| 连续补测，mkdir | 18.858 / 19.123 / 19.072 / 18.439 | CV 7.18%～8.71%，不稳定 |
| 连续补测，首次 stat | 1.787 / 1.803 / 1.790 / 1.796 | 最大 CV 3.76%，不能精确量化新增锁成本 |
| 连续补测，rmdir | 9.714 / 7.541 / 7.556 / 9.709 | 稳定快 22.17%～22.37% |
| 连续补测，整段 | 30.438 / 28.495 / 28.453 / 30.042 | 参考降幅 5.15%～6.52%，但 CV 4.52%～6.46%，不能声称稳定整体收益 |
| 50 ms 间隔，rmdir | 18.110 / 15.879 / 15.811 / 18.253 | 稳定快 12.32%～13.38% |
| 50 ms 间隔，整段 | 80.595 / 79.479 / 78.531 / 80.728 | 降幅 1.38%～2.72%；CV 0.59%～1.23%，A/B 漂移 +0.165% / −1.193% |

间隔版整段稳定性通过，改善低于预设 5% 晋级门槛，不等于收益为零。
间隔版 stat 的 CV 虽小于 3%，漂移仍为 −3.021% / −3.071%，不能说所有阶段都稳定。
原 binary 的 mkdir 及所有不稳定结果同样保留，没有删长尾或放宽门槛。

“整段”是用外层时钟直接测 mkdir 开始至 rmdir 返回，不是三个阶段中位数相加，
包括用户态衔接和读时钟。**50 ms 等待已排除，不能再减一次。**
另存的循环 wall time 包含等待和检查；这两种指标都不是包括全部异步回收的总 CPU 成本。
间隔改变了运行状态，不能据此证明异步回收是连续噪声的原因，或等待后回收一定完成。

## 机制与边界

单独的非计时跟踪确认每次仍处理 26 个 kernfs 节点，删除时 `ilookup()` 从 26 次变为 1 次，
属性写锁/包装读锁仍是 52/26 次。新增的写锁发生在首次 stat 初始化 inode 时，0→1 对。
补丁省掉的是从未初始化 inode 的节点查找，不是把这些查找移入 stat。
编译后 `kernfs_init_inode` 折入 `kernfs_get_inode`，不能把独立函数计数 0 当成没有初始化。

两个内核分别通过 16 次无 watch 删除、8 次文件/目录删除通知和 8 次保持 FD 打开的链接数检查。
这些检查不覆盖所有 inode 回收重建竞争，潜在等待环仍是源码审查结论而非已复现内核死锁。
